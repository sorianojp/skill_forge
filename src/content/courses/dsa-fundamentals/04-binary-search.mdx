**Binary Search** cuts the remaining search interval in **half** on every iteration. Even on 1,000,000 sorted elements, $\log_2(1,000,000) \approx 20$, so Binary Search finishes in at most **20 steps**.

<Callout type="tip" title="Avoid Integer Overflow in C/C++/Java">
  Always compute the midpoint as <code>lo + Math.floor((hi - lo) / 2)</code> (or <code>lo + (hi - lo) / 2</code> in C/Java/C#) instead of <code>(lo + hi) / 2</code>.
</Callout>

## Live DSA Playground

<Playground
  client:visible
  title="O(log n) Binary Search"
  defaultTab="js"
  showConsole={true}
  html={`<p>Watch how few steps Binary Search takes on a sorted array.</p>`}
  js={`function binarySearch(nums, target) {
  let lo = 0, hi = nums.length - 1, steps = 0;
  while (lo <= hi) {
    steps++;
    const mid = lo + Math.floor((hi - lo) / 2);
    if (nums[mid] === target) return { index: mid, steps };
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return { index: -1, steps };
}

const sorted = [3, 8, 15, 22, 31, 44, 59, 73, 88, 95];
console.log("Find 73:", binarySearch(sorted, 73));
console.log("Find 40:", binarySearch(sorted, 40));`}
/>
