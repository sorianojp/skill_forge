Unlike trees, **graphs** can contain cycles and disconnected components. Always maintain a **`visited` Set** (and add each neighbor to `visited` the moment you enqueue it, not when you dequeue it!) so BFS runs in linear **$O(V + E)$** time.

<Callout type="warning" title="Mark Visited Upon Enqueue in BFS">
  If you wait to mark a node visited until it is dequeued, the same node can be pushed onto the queue multiple times by different neighbors, causing slow duplicate work.
</Callout>

## Live DSA Playground

<Playground
  client:visible
  title="Shortest Path Hops via Graph BFS"
  defaultTab="js"
  showConsole={true}
  html={`<p>Find the fewest hops from HTML to React in a skill graph.</p>`}
  js={`const graph = {
  HTML: ["CSS", "JS"],
  CSS: ["HTML"],
  JS: ["TS", "Node"],
  TS: ["React"],
  Node: ["Docker"],
  React: [],
  Docker: []
};

function shortestHops(start, goal) {
  const visited = new Set([start]);
  const queue = [[start, 0]];
  for (let head = 0; head < queue.length; head++) {
    const [node, dist] = queue[head];
    if (node === goal) return dist;
    for (const next of graph[node] ?? []) {
      if (!visited.has(next)) {
        visited.add(next);
        queue.push([next, dist + 1]);
      }
    }
  }
  return -1;
}

console.log("HTML -> React hops:", shortestHops("HTML", "React"));
console.log("HTML -> Docker hops:", shortestHops("HTML", "Docker"));`}
/>
