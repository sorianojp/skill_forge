**Polymorphism** literally means "many forms." It lets callers invoke the same method name (such as `area()` or `pay(amount)`) on different object types, and each object executes its own specialized implementation.

## Killing Long `if / else` Chains

Without polymorphism, adding a new shape (`Triangle`) forces you to hunt down every `if (shape.type === 'circle') ... else if ...` block. With polymorphism, you simply create a new class that implements `area()`, and existing callers work automatically.

<Callout type="info" title="Interfaces in Typed Languages">
  In Java, C#, and TypeScript, you formalize a polymorphic contract with the <code>interface</code> keyword (for example, <code>interface Shape &#123; double area(); &#125;</code>). In C++, you use pure virtual functions.
</Callout>

## Try It Yourself (Live OOP Playground)

<Playground
  client:visible
  title="Polymorphic Payment Processors"
  defaultTab="js"
  showConsole={true}
  html={`<p>Checkout works with any payment class that implements charge(amount).</p>`}
  js={`class CardPayment {
  charge(amount) {
    return "Charged $" + amount + " via Credit Card";
  }
}

class WalletPayment {
  charge(amount) {
    return "Charged $" + amount + " via Digital Wallet";
  }
}

class BankTransfer {
  charge(amount) {
    return "Initiated $" + amount + " bank transfer";
  }
}

function checkout(processor, amount) {
  console.log(processor.charge(amount));
}

[new CardPayment(), new WalletPayment(), new BankTransfer()].forEach((p) => {
  checkout(p, 49);
});`}
/>
