**Encapsulation** means bundling an object's data with the methods that operate on it, and restricting direct outside access to internal state.

## Why Protect Internal State?

If a `BankAccount` exposes `account.balance` publicly, any caller could set `account.balance = -5000`. By making `#balance` private (or `private double balance` in Java/C#/C++), all changes must go through `deposit()` and `withdraw()`, where validation rules always run.

<Callout type="info" title="Access Modifiers Across Languages">
  Java, C#, C++, and PHP use keywords like <code>private</code>, <code>protected</code>, and <code>public</code>. Modern JavaScript uses the <code>#field</code> prefix for true runtime privacy.
</Callout>

## Try It Yourself (Live OOP Playground)

<Playground
  client:visible
  title="Encapsulated BankAccount"
  defaultTab="js"
  showConsole={true}
  html={`<p>Run the code to see how encapsulation blocks invalid withdrawals.</p>`}
  js={`class BankAccount {
  #balance;

  constructor(initialBalance) {
    this.#balance = Math.max(0, initialBalance);
  }

  deposit(amount) {
    if (amount <= 0) throw new Error("Deposit must be positive");
    this.#balance += amount;
  }

  withdraw(amount) {
    if (amount > this.#balance) {
      console.log("Rejected: insufficient funds");
      return false;
    }
    this.#balance -= amount;
    return true;
  }

  get balance() {
    return this.#balance;
  }
}

const acct = new BankAccount(100);
acct.deposit(50);
acct.withdraw(200);
acct.withdraw(40);
console.log("Final balance:", acct.balance);`}
/>
