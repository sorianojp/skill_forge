**Inheritance** allows a subclass to reuse fields and methods from a parent class (`AdminUser extends User`). **Composition** builds complex objects by combining smaller, focused objects (`Car` has an `Engine`).

## Favor Composition Over Deep Inheritance

Deep inheritance hierarchies (4+ levels) become fragile: changing one method in the root class can accidentally break distant subclasses. Use inheritance for true **is-a** relationships, and composition for **has-a** capabilities.

<Callout type="tip" title="Rule of Thumb">
  If a class only wants to borrow a helper capability (like logging, caching, or billing), inject that helper object via the constructor instead of inheriting from it.
</Callout>

## Try It Yourself (Live OOP Playground)

<Playground
  client:visible
  title="Inheritance + Composition Together"
  defaultTab="js"
  showConsole={true}
  html={`<p>Inspect how composition lets NotificationService swap channels cleanly.</p>`}
  js={`class User {
  constructor(name) {
    this.name = name;
  }
  role() {
    return "Learner";
  }
}

class Instructor extends User {
  constructor(name, track) {
    super(name);
    this.track = track;
  }
  role() {
    return "Instructor (" + this.track + ")";
  }
}

// Composition: Notifier is passed in rather than inherited
class EmailChannel {
  send(to, msg) {
    console.log("Email to " + to + ": " + msg);
  }
}

class WelcomeService {
  constructor(channel) {
    this.channel = channel;
  }
  welcome(user) {
    this.channel.send(user.name, "Welcome as " + user.role());
  }
}

const service = new WelcomeService(new EmailChannel());
service.welcome(new Instructor("Alex", "OOP"));`}
/>
