JavaScript values fall into **primitives** (`string`, `number`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) and **objects** (plain objects, arrays, functions, dates).

## Always Use Strict Equality (`===`)

Loose equality (`==`) silently coerces types (`"5" == 5` is `true`, `"" == 0` is `true`), causing subtle bugs. Strict equality (`===`) checks **both type and value**.

<DoDont
  doTitle="Strict Equality & Nullish Defaults"
  dontTitle="Surprising Type Coercion"
  doCode={`const score = 0;
const display = score ?? 100; // 0!
if (score === 0) { ... }`}
  dontCode={`const score = 0;
const display = score || 100; // 100 (bug!)
if ("0" == 0) { ... } // true!`}
  note="Use ?? when 0, false, or '' are valid values and you only want a fallback for null or undefined."
/>

<Callout type="note" title="The 6 Falsy Values">
  Only <code>false</code>, <code>0</code>, <code>""</code>, <code>null</code>, <code>undefined</code>, and <code>NaN</code> are falsy in JavaScript. Everything else (including empty arrays <code>[]</code> and objects <code>&#123;&#125;</code>)is truthy!
</Callout>
