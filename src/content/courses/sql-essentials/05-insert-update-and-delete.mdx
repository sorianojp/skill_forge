Modifying data is where SQL mistakes can be costly. One golden rule prevents disasters: **never run `UPDATE` or `DELETE` without a `WHERE` clause** unless you truly intend to overwrite or wipe the entire table!

<Callout type="warning" title="Golden Safety Habit">
  Before running <code>DELETE FROM users WHERE ...</code> on a real database, run <code>SELECT * FROM users WHERE ...</code> first to verify you matched the exact rows you intended.
</Callout>

## Try It Yourself

Notice how we insert a new row, update one row, and then `SELECT` the final table state:

<SqlPlayground
  client:visible
  title="INSERT, UPDATE & Inspect Results"
  schemaSql={`CREATE TABLE tasks (id INTEGER PRIMARY KEY, title TEXT, done INTEGER);
INSERT INTO tasks VALUES (1, 'Learn SELECT', 1), (2, 'Practice JOINs', 0);`}
  query={`INSERT INTO tasks (id, title, done) VALUES (3, 'Pass SQL Exam', 0);
UPDATE tasks SET done = 1 WHERE id = 2;

SELECT id, title, done FROM tasks ORDER BY id;`}
