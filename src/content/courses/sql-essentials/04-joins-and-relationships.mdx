Relational databases avoid repeating data by splitting entities into separate tables (like `learners` and `courses`) linked by **IDs**.

- **`INNER JOIN`**: Returns only rows that have a match in **both** tables.
- **`LEFT JOIN`**: Returns **all** rows from the left table, with `NULL` for columns when the right table has no match.

<Callout type="tip" title="Spotting Unmatched Records">
  A <code>LEFT JOIN</code> followed by <code>WHERE right_table.id IS NULL</code> is the classic SQL pattern to find learners who have not enrolled in any course yet!
</Callout>

## Try It Yourself

Try changing `LEFT JOIN` to `INNER JOIN` below and watch what happens to **Noah** (who has no certificate yet)!

<SqlPlayground
  client:visible

CREATE TABLE certificates (id INTEGER PRIMARY KEY, learner_id INTEGER, course TEXT);

INSERT INTO certificates VALUES (1, 1, 'HTML'), (2, 2, 'SQL');`}
