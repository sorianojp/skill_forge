Imagine transferring 50 points from one account to another: two `UPDATE` statements must **both succeed or both fail**. Wrapping them in a **transaction** guarantees **Atomicity** (all-or-nothing).

```sql
BEGIN TRANSACTION;
UPDATE wallets SET points = points - 50 WHERE id = 1;
UPDATE wallets SET points = points + 50 WHERE id = 2;
COMMIT;
```

If anything fails before `COMMIT`, running **`ROLLBACK`** cleanly restores the database to its exact state before `BEGIN TRANSACTION`.

## Try It Yourself

Notice how the `ROLLBACK` below undoes the accidental `UPDATE`, keeping Maya's points safely at `100`:
