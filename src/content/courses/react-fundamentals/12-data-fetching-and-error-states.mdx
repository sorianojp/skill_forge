When a user switches tabs quickly (`courseId = 1` then `courseId = 2`), the slower request for `1` might arrive *after* `2` and overwrite the screen with stale data. Passing an **`AbortController`** signal to `fetch(url, { signal })` and calling `controller.abort()` in the `useEffect` cleanup eliminates this race condition cleanly.

<Callout type="warning" title="fetch() Does Not Reject on HTTP 404 or 500">
  Always check <code>if (!res.ok) throw new Error("HTTP " + res.status)</code> before calling <code>res.json()</code>.
</Callout>

  else el.textContent = "Loaded " + state.data.length + " tracks: " + state.data.join(", ");
}
