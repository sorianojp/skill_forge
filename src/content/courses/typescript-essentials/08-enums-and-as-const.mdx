Modern TypeScript teams often prefer **`as const` objects** over `enum` because `as const` emits zero extra runtime wrapper code while preserving exact literal types. Pairing it with **`satisfies`** validates the structure without widening literal values to plain `string`.

<Callout type="tip" title="satisfies Gives You Both Validation and Narrow Types">
  <code>const palette = &#123; primary: "#2563eb" &#125; satisfies Record&lt;string, string&gt;;</code> checks that all values are strings while still remembering that <code>palette.primary</code> exists specifically.
</Callout>
