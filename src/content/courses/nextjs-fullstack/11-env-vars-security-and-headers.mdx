## Overview

Separate server-only secrets from NEXT_PUBLIC_ browser variables and configure security headers in next.config.ts.

Next.js App Router unifies server rendering, streaming, type-safe mutations, and edge-ready caching inside a single React + TypeScript codebase.

## Production Code Example

```tsx
// next.config.ts
const nextConfig = {
  async headers() {
    return [{
      source: '/(.*)',
      headers: [
        { key: 'X-Content-Type-Options', value: 'nosniff' },
        { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
      ],
    }];
  },
};
export default nextConfig;
```

<Callout type="tip" title="Next.js Best Practice">
Keep Server Components as your default, validate every Server Action and Route Handler input on the server, and verify your production bundle size with `next build` before shipping.
</Callout>

## Key Takeaways

- **Never prefix database passwords or API secrets with NEXT_PUBLIC_**
- **Use the server-only package to guard secret helper modules at build time**
- **Configure X-Content-Type-Options, Referrer-Policy, and CSP headers**
