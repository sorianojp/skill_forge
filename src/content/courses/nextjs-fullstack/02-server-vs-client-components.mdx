## Overview

Understand why components in app/ are Server Components by default and where to place 'use client' leaves.

Next.js App Router unifies server rendering, streaming, type-safe mutations, and edge-ready caching inside a single React + TypeScript codebase.

## Production Code Example

```tsx
// app/courses/LikeButton.tsx
'use client';
import { useState } from 'react';

export function LikeButton({ initial }: { initial: number }) {
  const [likes, setLikes] = useState(initial);
  return <button onClick={() => setLikes((n) => n + 1)}>Likes: {likes}</button>;
}
```

<Callout type="tip" title="Next.js Best Practice">
Keep Server Components as your default, validate every Server Action and Route Handler input on the server, and verify your production bundle size with `next build` before shipping.
</Callout>

## Key Takeaways

- **Keep data fetching and secrets inside Server Components with zero client JS cost**
- **Add 'use client' only at interactive leaves that need hooks or browser events**
- **Pass Server Components as children props into Client Components cleanly**
