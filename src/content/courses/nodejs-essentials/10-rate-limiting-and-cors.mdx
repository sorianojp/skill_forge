Public API endpoints (like login, signup, or a live code runner) should always enforce **rate limiting** (`429 Too Many Requests`) and **payload size limits** so a single misbehaving client cannot overload your server.

<Callout type="info" title="CORS Is Enforced by Browsers">
  Setting <code>Access-Control-Allow-Origin</code> to your exact frontend origin (rather than <code>*</code> when credentials are used) keeps cross-origin requests tight and secure.
</Callout>

## Live Code Lab (Node.js 20)

<CodeLab
  client:visible
  title="rate_limiter.js"
  language="node"
  code={`const buckets = new Map();

function allow(ip, limit = 3) {
  const count = (buckets.get(ip) ?? 0) + 1;
  buckets.set(ip, count);
  return count <= limit;
}

for (let i = 1; i <= 4; i++) {
  console.log("Req", i, "->", allow("10.0.0.1") ? "200 OK" : "429 Too Many Requests");
}`}
  expectedOutput={`Req 1 -> 200 OK
Req 2 -> 200 OK
Req 3 -> 200 OK
Req 4 -> 429 Too Many Requests`}
/>
