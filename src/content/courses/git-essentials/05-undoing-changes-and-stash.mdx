Every developer makes mistakes in Git. Knowing which undo command matches your situation prevents panic and data loss.

## Choosing the Right Undo Tool

| Situation | Recommended Command | Safe on Shared Branch? |
| :--- | :--- | :--- |
| Need to switch branches mid-edit | `git stash` / `git stash pop` | Yes |
| Discard unstaged edits in a file | `git restore file.js` | Yes |
| Undo a commit already pushed to `main` | `git revert <hash>` | Yes (adds an inverse commit) |
| Move a local unpushed commit back to staging | `git reset --soft HEAD~1` | Local only |

<Callout type="warning" title="Revert vs. Reset">
  Use <code>git revert</code> for commits already shared with others because it preserves history by creating a new commit that reverses the bug. Reserve <code>git reset</code> for local, unpushed commits.
</Callout>
