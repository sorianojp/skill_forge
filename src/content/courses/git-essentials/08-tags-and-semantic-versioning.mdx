**Git tags** pin human-readable release names like `v1.0.0` or `v2.3.1` to specific commits. Unlike branches, tags do not move as new commits are added.

## Semantic Versioning (SemVer)

- **MAJOR (`2.0.0`)**: Breaking API changes.
- **MINOR (`1.3.0`)**: Backward-compatible new features.
- **PATCH (`1.2.1`)**: Backward-compatible bug fixes.

<Callout type="tip" title="Prefer Annotated Tags for Releases">
  <code>git tag -a v1.0.0 -m "Initial release"</code> stores the tagger, date, and release message, making it ideal for GitHub Releases and CI deploys.
</Callout>
