**`git rebase`** moves or replays your local feature branch commits on top of the latest `main`, creating a linear history without extra merge commits.

## Merge vs. Rebase

- **Merge** preserves exact branching chronology and never rewrites commit hashes.
- **Rebase** replays your commits onto a new base commit (producing new hashes) for a crisp, linear log.

<Callout type="warning" title="The Golden Rule of Rebasing">
  Never run <code>git rebase</code> on a branch that teammates already pulled (like <code>main</code>). Only rebase your own local or private feature branch.
</Callout>
