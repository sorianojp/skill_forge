## The Four Pillars of OOP

| Pillar | Meaning | Practical Goal |
| :--- | :--- | :--- |
| **Encapsulation** | Hide internal state behind public methods | Protect invariants and prevent invalid mutations |
| **Abstraction** | Expose essential operations, hide complexity | Keep callers simple and decoupled |
| **Inheritance** | Subclass extends a base class (`is-a`) | Share common structure when a true subtype exists |
| **Polymorphism** | Different classes share one method contract | Plug in new behavior without `if/else` chains |

## The Five SOLID Principles

| Letter | Principle | Summary |
| :--- | :--- | :--- |
| **S** | Single Responsibility | One class, one focused reason to change |
| **O** | Open / Closed | Extend behavior with new classes instead of editing stable ones |
| **L** | Liskov Substitution | Any subclass must work safely wherever its parent is expected |
| **I** | Interface Segregation | Prefer small, role-specific interfaces over huge ones |
| **D** | Dependency Inversion | Inject abstractions via constructors rather than hardcoding concretions |
